# 财务口径与放行规则

- 原始 PDF、MinerU 输出、候选数据和导出结果分层保存。每个任务用新目录，历史结果不覆盖。
- 三份 SQL 是物理结构，未提供完整业务代码字典。`STATEMENT_TYPE`、`S_INFO_COMPCODE`、两个证券代码字段的关系、`OBJECT_ID`、`timetag`、`seq` 必须有经确认的规则。
- `business_rules.status=confirmed` 表示已有真实业务确认依据，`reference` 写该依据的位置或说明。不得仅为获得 ready 状态自行改成 confirmed。
- 利润表、现金流量表公司 ID 必填。三个表的 timetag、seq 分别单列唯一。系统不生成假供应商 ID，不提供 INSERT IGNORE、REPLACE 或静默覆盖历史值。
- 公告日期、实际公告日期、报告期相互区分。缺少公告日期时可空，不以文件时间代替。日期输出 YYYYMMDD。
- 一张来源年报可能包含两个期间。分别建立候选记录，保留原列标题；历史比较数不能自动覆盖以前披露的记录。
- 默认金额单位为“待确认”，从具体表头核实后填写 yuan / wan_yuan / yi_yuan。每股收益用 yuan_per_share；TOT_SHR 用 shares / wan_shares。CAP_STK 是金额科目，不能凭名称当成股数。
- 空白、短横线和“未披露”默认保留 null。明确写出的 0 才是零。暂不支持用报表说明将短横线自动变成零；需复核后扩展规则。
- 金额以原始字符串输入，经 Decimal 换算为四位小数。超过目标精度、非法分组和需额外舍入的金额阻止放行。
- 不以三张主表填满所有 SQL 字段。衍生指标、差额项目、间接法和附注字段不擅自计算或补全。
- `OTH_RCV` 与 `OTH_RCV_TOT`、`FIX_ASSETS` 与 `STM_BS_TOT`、`CONST_IN_PROG` 与 `CONST_IN_PROG_TOT` 等需按合计/明细口径核对。关键词相同不自动确认。
- 非空待匹配项目、未确认字段映射及无法定位的证据均须列明。证据块包含某个数字不保证列选择正确，智能体仍须核对表头和行列。
- 默认金额勾稽容差 0.01 元。变更须有披露精度依据，工具允许 0 至 1 元，超过该范围需明确修改和复核规则。
- 必需勾稽：资产=负债+含少数股东权益；净利润=利润总额-所得税；现金期末=期初+净增加额；现金净增加额=三类活动净额+汇率影响。缺项标为不可校验，不用零代替。
- 当前工具只验证批次内的键冲突，未连接数据库，因此不能证明与已有数据库记录无冲突。
- 用户提供本地 PDF，parse 会将选取的页面上传 MinerU 在线 API。使用范围和授权遵守项目约定；不自动采集外部财报。Claude Code 的模型调用由宿主负责，MinerU 使用独立 Token。
